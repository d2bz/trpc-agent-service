## 平台限制的明确边界

- 长度：当前企微按 20480 字节处理 UTF-8，超长尾部替换为 `[truncated]`，持久化与发送同一正文。增量流和多终态分片不能互相替代；飞书按具体消息类型的上限配置，尚未做平台实测。
- 限频：生产设计在外部账号作用域设置发送配额，并保持同会话顺序；按消息/API 类型配置额度，只有确认可重试的限流才安排有上限的指数退避，平台提供有效重试等待值时优先遵守。当前串行消费者不是完整限流器，单次终态发送策略保持不变。
- 异步：Inbox/Run 事务提交与模型执行分开；Webhook 提交后快速确认，企微长连接没有可假定的入站 HTTP ACK。最终结果通过 Outbox 发送，不把平台本地请求超时当成回复有效期。
- 媒体：设计由 Adapter 下载/解密、校验大小和类型，保存受租户权限保护的附件引用；出站先上传媒体再生成平台消息。当前只受理单聊纯文本，图片/文件及混合消息不进入 Runner，不静默丢附件后只处理文字。
- 撤回：验证事件与原消息关联，保留 Session/Audit，不自动撤销已执行 Tool；平台支持时通过 Outbox 撤回机器人回复，否则按租户策略忽略或更正。当前未实现。
- 重试：入站重复 msgid 命中已有 Inbox/Run；出站失败不创建新 Run。当前回复最多尝试一次，回执未知、旧连接目标过期均不自动重发。跨连接可重试、查询投递状态及 exactly-once 均不属于已验证保证。

平台限频数值、回复有效期、入站补投和跨连接回复能力仍待官方依据或专门联调核实，列为风险登记。其影响是限流拒绝、超期投递失败或未持久化消息丢失；当前遇到拒绝/未知按上述保守边界结束。生产监测队列年龄、连接中断、持久化失败、回执超时和投递结果，再决定配额和恢复能力，不因待核实项继续扩大本切片。
